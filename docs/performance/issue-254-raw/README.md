## Limiter

`profile.sh` records separate native manager and real CLI worker/launcher CPU profiles and manager GC traces, never included in the comparative samples. In the independent manager baseline, self samples attribute 15.73 seconds to `loadEntriesFromFile`, 2.02 seconds to GC, and 0.31 seconds to line parsing. The candidate attributes 0.16 seconds to the loader, 0.30 seconds to line parsing and 0.19 seconds to StringDecoder. The actual CLI worker profiles show the same transition; launchers mostly wait. Native JSON parsing and decoding now dominate this local path.

The baseline repeatedly concatenates a growing pending line and calls `indexOf` from zero. Profile position ticks identify that search. Node v24.22.1's V8 `String::IndexOf` explicitly flattens its receiver in `deps/v8/src/objects/string.cc:1476` before searching. The exact public source is retained as `v8-string.cc` and is available at https://github.com/nodejs/node/blob/v24.22.1/deps/v8/src/objects/string.cc#L1466-L1492. The repair scans only the new decoded chunk and joins fragments at the existing native JSON.parse boundary. It introduces no custom JSON parser, async API, cache, storage format, context policy, history limit, or public seam.
