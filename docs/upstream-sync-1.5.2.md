# Upstream integration: v1.5.2

## Baseline

This integration merges upstream main `6273031b012ab3c017cdbf593a62b7e6792186a8` into fork
`212d9a12c1be60cf6e8f407536a56611fa5c7654`, preserving both histories. The preceding upstream
baseline is `4ea8837927564c592b1d184c956ab7d28c88119b`. There are 24 incoming non-merge commits.

Official v1.5.2 (`b4afdddf44e059c67ccf5097e5317d913521b470`) is in this range. Upstream main is
four commits after it: the new `[Unreleased]` sections and three p2 sidebar commits.

## Incoming changes

- **Release v1.5.2**: package versions and changelog sections.
- **Coding agent**: no new code. The missing-directory prompt and the `/import` copy fix, both
  merged on 2026-11-10, move from `[Unreleased]` to `[1.5.2]`. The llama.cpp guide uses the
  unified `llama` entry point.
- **AI**: Anthropic OAuth requests report Claude Code 2.1.322.
- **Chord**: documents and table rows can belong to a host. The store schema is version 3, which
  adds an indexed `host` column. One address's data can be exported, imported and deleted, and
  the archive format is version 2. Workers start without `--enable-source-maps`; the worker
  base's source maps are files beside it, and a facet's map is parsed at the first stack lookup.
  `@earendil-works/chord/compression` exports Node's origin compression.
- **Durable**: the design documents for suspendable work. No code.
- **p2**: a Settings window replaces the sidebar footer's More menu. Views open beside the
  transcript. The working wheel's latest thought shows below it. The sidebar groups sessions into
  rollups. A conversation switch no longer fetches page-wide objects again, and large parts are
  compressed. Session workers cap V8's young generation at 2 MiB per semi-space.
- **p3**: design documents only.
- **Other packages**: version numbers only.

Pi's terminal interface is unchanged.

Two decisions outside the conflicts:

- **The keyed pin fix stays.** Upstream's new `adoptChanged` marks a key ready when a host data
  change replaces it. A commit's `adopt` still does not in upstream. With the fork's line removed
  from `adopt`, the fork's two tests fail on this merge.
- **Changelog repair.** The `[1.5.0]` coding-agent section regains upstream's entry for two
  processes refreshing OAuth credentials through different paths to `auth.json`. It had been
  missing from the fork's copy of that released section.

No automatically merged file needed a hand edit. Nine source files and four test files changed
on both sides without a textual conflict; the suites below cover the fork behavior in each.

## Verification

All runs used macOS. Root suites ran on Node 24.22.2 and p2 on Node 26.13.0. Providers were
offline or faux. The results are for the merge with fork main
`faa9b394ce975f373b9fb9638cf6c51568756ba9` merged in. Fork main
`e46e3a599fe01cb0b5e589ca4def0a39c0a990e4`, merged afterwards, adds only the Claude Code version

  tests and 24,846 package tests. pi-schema's suite also reports its nine expected failures.

  `test/suite/working-session-files.test.ts` ("above Node's string limit"): a completion file
  was missing. The test then passed alone 3 of 3 times, in 4 further runs of its suite, and in
  the two later full runs. The cause is not established. The merge changes no code on that path.

  `keyed-slot.test.ts` fail. With it, Chord's keyed-slot, store, host-data and workers test
  files pass all 156 tests.

## Baseline runs on macOS

Upstream's four Chrome launchers do not pass `--use-mock-keychain`. Under `./test.sh` the home
directory is isolated and has no keychain, so each Chrome start from an untouched upstream
checkout opens a Keychain dialog on the desktop and can block. Baseline runs on such a checkout
set `CHROMIUM_BIN` to a wrapper script that adds the flag. The fork's four launchers pass the
flag themselves, and this merge keeps it in all four.
