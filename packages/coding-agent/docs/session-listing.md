# Session listing cache

`SessionManager.list()` and `SessionManager.listAll()` cache the complete result of a journal scan. The resume picker uses these APIs. Exact message counts, names, activity dates, first-message previews, and full user and assistant search text are unchanged. Search still includes abandoned branches and excludes tool output.

Each source directory can contain a private `.session-list-cache-v1` directory. A journal named `example.jsonl` has a derived `example.json` record there. Cache records contain plaintext conversation text. On POSIX systems the directory has mode `0700`, and records have mode `0600`. Windows uses inherited directory permissions. Keep the cache private with the session directory. Version-2 records reuse this directory; older records without a content digest are rebuilt, not accepted as hits.

A cache hit requires the same device, inode, byte length, nanosecond modification time, and nanosecond change time **and a matching SHA-256 of the entire journal**. Metadata is only a quick rejection: an already-dirty shared memory mapping can change bytes without changing any of those stat fields. Every warm hit therefore streams all raw journal bytes, but avoids parsing the JSONL again. Pi checks the source revision around validation and rechecks date context after hashing.

Records also identify the date-parser context: Node, ICU and timezone-data versions, `TZ`, and the effective timezone. A different runtime or timezone rescans the source, preserving accepted timestamps that omit a zone. Each public listing lazily shares this context across its reads, recomputing it if the raw `TZ` value or `Intl.DateTimeFormat` function identity changes. Unavailable context disables caching rather than hiding a session; later lookups retry resolution. A cold scan that observes unavailable or changed context while parsing dates is not published, even if the context subsequently recovers. Publication still performs full context validation.

The first listing, or a listing after a source change, still parses the complete journal. Its digest comes from the exact raw chunks consumed by that scan, not decoded strings or a later reread. Pi does not approximate counts, truncate searchable text, or resume parsing from an old byte offset. Valid unterminated records and malformed final fragments retain their original behavior. Listing and cache cleanup never modify source bytes.

Cache publication uses an exclusive temporary file and atomic rename. A scan whose source revision changes is not cached. A changed revision or mismatching digest drops obsolete cached text even if the replacement cannot be cached. Independent writers need no shared manifest or lock. A digest saved with an older scan cannot authorize reuse for different source bytes. Listing remains a best-effort observation during concurrent writes, not an atomic filesystem snapshot: a writer can still change a journal after it has been read.

Every listing discovers current source files again. A renamed path appears under its new name, and a deleted journal is not returned. Listing removes orphaned records and temporary publications in each discovered source directory, including records for dangling journal symlinks. Empty or non-session sources and non-abort scan errors also remove the path's final and temporary cache records, including a journal path replaced by a directory. Cancellation alone does not trigger failed-scan invalidation. Skipping a valid session only because its cwd differs from the requested project does not invalidate an otherwise-valid cache record. Successful picker deletion also removes the associated final and temporary records. Writers recheck the source around publication so a running writer does not recreate a deleted journal's cache.

Deleting an entire source directory removes its cache. An external single-file deletion leaves its derived records until the next listing of that directory. Cleanup is best-effort: permissions or storage errors can delay removal. Abandoned temporary publications are retained while the source remains unchanged and valid, rather than racing a writer that may still own them. Digest-mismatch and failed-scan cleanup remove matching abandoned publications.

Missing, invalid, unsupported, or unavailable cache records fall back to source scans. Read-only source directories remain listable but cannot populate a cache. Unsupported date values remain on the uncached path. No cache file is a session or a substitute for a journal.

Warm listing cost includes directory discovery, revision checks, full journal reading and hashing, cache decoding, and the complete search text. A digest mismatch may require both a validation read and an authoritative parsing read. Storage grows with searchable text, not just the session count. The cache does not change per-keystroke search normalization, provider behavior, or session-open parsing. See [dated synthetic Linux measurements](https://github.com/fitchmultz/pi/blob/2b6e076c76b9aeec0cfee7a3051a6931a464d41e/docs/performance.md#session-listing-2026-10-25) for the content-validated implementation and its limits; historical metadata-only timings do not qualify it.
